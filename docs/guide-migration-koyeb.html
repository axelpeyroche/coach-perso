Quitter Render pour Koyeb, pas à pas

Guide préparé le 17/11/2026, pour une migration début janvier 2027. Toutes tes données restent dans la base Neon : seul l'endroit où tourne l'application change.

0 étape cochée

En bref

  • Durée totale : environ 1 h 30 le jour J, plus 10 min par appareil, et une dernière étape un mois plus tard.
  • Coût : 0 €. Koyeb demande une carte bancaire à l'inscription, bloque 29 $ puis les débloque aussitôt.
  • Il te faut : accès à Render, GitHub, UptimeRobot, developer.spotify.com, une carte bancaire, ton iPhone et ton ordinateur.
  • Quand : à partir du 1er janvier. Ce jour-là, Render a de nouveau des heures gratuites, donc l'ancienne version peut redémarrer en cas de retour arrière.
  • Qui fait quoi : Toi pour tout ce qui touche à tes comptes, Claude pour le code et les vérifications, Tout le monde pour chaque appareil, invités compris.

Tes cases cochées et l'adresse restent mémorisées dans ce navigateur. Tu peux fermer la page et revenir plus tard.

A Préparer la veille · 15 min

ToiTélécharger une sauvegarde complète

  1. Ouvre Mon Carnet (l'adresse actuelle) puis Profil.
  2. Section Données du compte : touche Sauvegarde complète (JSON).
  3. Range le fichier dans un endroit sûr (pas dans le dossier du code).

La migration n'écrit rien dans la base. C'est une précaution.

ToiVérifier la restauration chez Neon

  1. Connecte-toi sur console.neon.tech et ouvre le projet de Mon Carnet.
  2. Dans les réglages du projet, regarde la durée d'historique conservée (history retention / restore window).

Ne change rien : il s'agit seulement de savoir jusqu'où tu pourrais revenir en arrière.

ToiRepérer les variables à recopier sur Render

Sur dashboard.render.com, ouvre le service coach-perso (l'API), puis l'onglet Environment. Note la liste des noms présents. Les valeurs, tu les copieras directement de Render vers Koyeb à l'étape B3.

Ouvre aussi le site statique coach-perso-frontend, onglet Environment : repère VITE_SPOTIFY_CLIENT_ID. Chez Koyeb, la même valeur s'appellera SPOTIFY_CLIENT_ID.

Ne recopie pas PYTHON_VERSION ni VITE_API_URL : ils ne servent plus.

Ne colle jamais ces valeurs dans une conversation avec une IA, Claude compris. Copie-les directement de l'onglet Render vers l'onglet Koyeb.

B Créer le service Koyeb 30 min, dont 5 à 10 d'attente

Pendant toute la phase B, Render continue de tourner. Ni toi ni tes invités ne voyez de différence.

ToiCréer le compte Koyeb

  1. Va sur app.koyeb.com et inscris-toi avec ton compte GitHub : la connexion au dépôt sera déjà faite.
  2. Choisis l'offre gratuite (Hobby). Ne prends pas d'offre payante.
  3. Entre ta carte bancaire. Koyeb bloque 29 $ pour vérifier la carte, puis débloque aussitôt. Rien n'est facturé sur l'instance gratuite.

ToiLancer la création du service

  1. Create Web Service (ou Create service), puis GitHub.
  2. Si Koyeb demande l'accès à GitHub, choisis Only select repositories et coche seulement le dépôt de Mon Carnet.
  3. Choisis le dépôt et la branche master.
  4. Builder : Dockerfile. Le fichier est à la racine du dépôt. Laisse vides le chemin, la commande et les arguments : tout est déjà dans le Dockerfile.
  5. Instance : celle nommée Free.
  6. Region : Frankfurt, là où est la base Neon. Les requêtes seront plus rapides.

Ne clique pas encore sur Deploy.

ToiRecopier les variables

  1. Section Environment variables (and files) : ajoute une ligne par variable repérée en A3, avec le même nom et la même valeur que sur Render.
  2. Pour les valeurs sensibles (DATABASE_URL, JWT_SECRET, VAPID_PRIVATE_KEY, ORS_API_KEY), choisis le type Secret si Koyeb le propose.
  3. Ajoute SPOTIFY_CLIENT_ID avec la valeur de VITE_SPOTIFY_CLIENT_ID du site statique. Cette valeur n'est pas secrète.
  4. N'ajoute ni PORT ni DOSSIER_INTERFACE : c'est déjà réglé.
Vérifie chaque valeur deux fois : un espace en trop au début ou à la fin suffit pour que DATABASE_URL ou JWT_SECRET ne marchent plus.

ToiPort et contrôle de santé

  1. Exposed ports : port 8000, protocole HTTP, chemin /. C'est souvent la valeur par défaut.
  2. Health checks : remplace TCP par HTTP, chemin /health, port 8000.
  3. S'il existe un champ Grace period, mets 60 s : au premier démarrage, l'app vérifie la base avant d'ouvrir.

ToiNommer et déployer

  1. Service name : par exemple mon-carnet. L'adresse sera du type https://mon-carnet-<ton-organisation>.koyeb.app. C'est elle que tes invités utiliseront : choisis un nom simple.
  2. Laisse activé le redéploiement automatique à chaque push sur master.
  3. Clique sur Deploy. La première construction prend 5 à 10 minutes : interface, puis Python.
  4. Quand le statut passe à Healthy (vert), copie l'adresse publique du service et colle-la en haut de cette page.

ToiLire les journaux de démarrage

Dans le service Koyeb, onglet Logs (journaux d'exécution, pas ceux de construction), tu dois voir :

  • [startup] Tables et migrations OK.
  • puis une ligne d'uvicorn du type Uvicorn running on http://0.0.0.0:8000.

Si le déploiement échoue, va voir En cas de problème.

Claude vérifie, sans rien écrire :

  • la page d'accueil s'affiche ;

ToiEssai sur ordinateur

  1. Ouvre [adresse Koyeb] dans ton navigateur.
  2. Connecte-toi avec ton e-mail et ton mot de passe habituels. C'est la même base, donc le même compte.
  3. Vérifie le carnet (toutes tes séances), une fiche d'activité avec sa carte, un itinéraire et le Plan.
Si tout s'affiche, la partie difficile est faite. N'active pas encore les notifications sur cette adresse : ce sera à l'étape F3.

D Couper les anciennes notifications 2 min par appareil

Tout le mondeDésactiver les notifications dans l'ancienne app

À faire avant la bascule, tant que l'ancienne API Render répond. Sinon, un appareil risque de recevoir chaque notification en double : une par l'ancienne app, une par la nouvelle.

  1. Sur chaque appareil où les notifications sont actives (iPhone, ordinateur…), ouvre l'ancienne Mon Carnet.
  2. Profil, section Notifications : désactive Notifications du matin.

Pour tes invités, envoie le premier message de l'étape G4 quelques jours avant.

Un oubli n'a rien de grave : voir « notifications en double » dans En cas de problème.

E La bascule 20 min, dans cet ordre

ToiDiriger la synchro du matin vers Koyeb

  1. Sur GitHub, ouvre le dépôt de Mon Carnet, puis Settings.
  2. Menu de gauche : Secrets and variables > Actions, puis l'onglet Variables. Pas l'onglet Secrets.
  3. New repository variable :
    • Name : CARNET_API_URL
    • Value : [adresse Koyeb] , sans /api et sans barre finale.
  4. Add variable.

ClaudeLe commit du jour J

Envoie à Claude : Bascule Koyeb : fais le commit du jour J avec [adresse Koyeb].

Claude met à jour :

  • l'adresse de l'outil d'envoi IA (outils/carnet.py) ;
  • la fiche des raccourcis iOS ;
  • la page Confidentialité : application chez Koyeb, base chez Neon à Francfort ;
  • la synchro du matin, qui repasse à deux passages par heure pour une notification à 10 min près.

Koyeb se redéploie tout seul après le push (environ 5 min).

ToiAutoriser la nouvelle adresse chez Spotify

  1. Va sur developer.spotify.com > Dashboard, puis ouvre ton app.
  2. Settings > Edit. Dans Redirect URIs, ajoute [adresse Koyeb]/spotify .
  3. Garde l'ancienne adresse pour l'instant, puis Save en bas de la page.

ToiGarder Koyeb éveillé avec UptimeRobot

  1. Sur uptimerobot.com, s'il reste un ancien moniteur vers onrender.com, supprime-le. Il ne faut jamais pinguer Render.
  2. New monitor :
    • type HTTP(s) ;
    • URL [adresse Koyeb]/health ;
    • intervalle de 10 minutes (tout ce qui est sous 1 h suffit).
  3. Enregistre. Le moniteur doit passer au vert (Up) en quelques minutes.

Chez Koyeb, l'instance s'endort après 1 h sans visite. Ce moniteur l'en empêche, sans rien consommer ni coûter.

ToiRediriger l'ancienne adresse

  1. Sur Render, ouvre le site statique coach-perso-frontend, onglet Redirects/Rewrites.
  2. Il y a une règle /* → /index.html (action Rewrite). Modifie-la :
    • Source : /*
    • Destination : [adresse Koyeb]/*
    • Action : Redirect
  3. Save, puis ouvre l'ancienne adresse coach-perso-frontend.onrender.com : tu dois arriver sur Koyeb.

Pendant un mois, les anciens favoris et les liens déjà envoyés mèneront à la bonne adresse. Un site statique ne consomme aucune heure Render.

Si la page du service mentionne un Blueprint, dis-le à Claude : il fera la même modification dans render.yaml, sinon Render pourrait remettre l'ancienne règle.

ToiSuspendre l'ancienne API Render

  1. Sur Render, ouvre le service coach-perso (l'API), puis Settings.
  2. Tout en bas : Suspend Web Service.
Suspendre, pas supprimer. Pendant un mois, c'est ton retour arrière. Un service suspendu ne consomme aucune heure.

I Un mois plus tard : adieu Render 10 min

ClaudeNettoyer le code

Envoie à Claude : Koyeb tourne depuis un mois, retire Render du code.

Claude supprime render.yaml et les anciennes adresses Render qui restent dans le code.

ToiSupprimer les services Render

  1. Service coach-perso (l'API suspendue) : Settings > Delete Web Service, puis confirme en tapant le nom.
  2. Site coach-perso-frontend (la redirection) : Settings > Delete Static Site. Fais-le quand tes invités utilisent tous la nouvelle adresse.

Tes 3 autres outils gardent les 750 h gratuites de Render pour eux seuls.

ToiSpotify : retirer l'ancienne adresse de retour

Sur developer.spotify.com, dans les réglages de l'app, supprime l'adresse https://coach-perso-frontend.onrender.com/spotify, puis Save.

↺ Retour arrière avant la phase I seulement

Si quelque chose ne va pas chez Koyeb et que tu veux revenir à Render en attendant :

  1. Render, service coach-perso : Resume Web Service.
  2. Render, site coach-perso-frontend, Redirects/Rewrites : remets la règle /* → /index.html, action Rewrite.
  3. GitHub, Variables : supprime CARNET_API_URL. La synchro retourne vers Render.
  4. UptimeRobot : mets le moniteur Koyeb en pause et ne crée surtout pas de moniteur vers Render.
  5. Préviens Claude, qui rétablit les adresses Render dans le code si besoin.
Il n'y a aucune donnée à restaurer : Render et Koyeb lisent la même base. Ce qui a été saisi sur Koyeb reste visible sur Render.

? En cas de problème

La construction échoue chez Koyeb (Build failed)

Ouvre les journaux de construction (Build logs) et copie à Claude les 30 dernières lignes, en vérifiant qu'elles ne contiennent aucune valeur secrète. C'est en général une dépendance à corriger dans le code. Render n'est pas touché.

Le service reste « Unhealthy » ou redémarre en boucle
  • Vérifie que le contrôle de santé est en HTTP sur /health, port 8000.
  • Allonge la grace period (60 à 120 s).
  • Dans les journaux d'exécution, cherche une erreur de connexion à la base : c'est presque toujours DATABASE_URL mal recopiée (espace, guillemet, morceau manquant).
Page blanche ou « Erreur serveur interne » après connexion

Vide le cache de la page (sur ordinateur, rechargement forcé : Ctrl+Maj+R). Si l'erreur persiste, regarde les journaux Koyeb au moment de l'erreur et transmets la ligne d'erreur à Claude.

« Session expirée » ou jeton refusé en boucle

JWT_SECRET n'est pas identique à celui de Render. Recopie-le, enregistre : Koyeb redéploie seul.

Aucune notification n'arrive
  • Vérifie les trois variables VAPID_… : elles doivent être identiques à Render.
  • Sur iPhone, les notifications ne marchent que depuis l'icône de l'écran d'accueil, pas dans Safari.
  • Réglages iOS > Notifications > Mon Carnet : autorisées ?
  • Utilise Envoyer une notification de test dans Profil.
Notifications en double sur un appareil
  • iPhone : supprime l'ancienne icône Mon Carnet. L'ancien abonnement meurt avec elle et le serveur le retire au premier envoi refusé.
  • Ordinateur : dans les réglages du navigateur, section Notifications, bloque le site coach-perso-frontend.onrender.com.
  • Sinon, dans la nouvelle app, sur l'appareil principal : Profil > Ne garder que cet appareil. Réactive ensuite les notifications sur tes autres appareils.
Spotify affiche « INVALID_CLIENT: Invalid redirect URI »

L'adresse [adresse Koyeb]/spotify n'est pas, à l'identique, dans les Redirect URIs de l'app Spotify (étape E3). Vérifie le https, l'absence de barre finale et le Save. Si le bouton Spotify n'apparaît pas du tout dans Profil, c'est SPOTIFY_CLIENT_ID qui manque chez Koyeb.

La synchro du matin échoue (croix rouge sur GitHub)
  • Code 404 : la variable CARNET_API_URL se termine probablement par /api ou par une barre. Mets seulement [adresse Koyeb].
  • Code 401 ou 403 : le secret GitHub CARNET_IMPORT_TOKEN n'a pas bougé. C'est donc JWT_SECRET qui diffère chez Koyeb.
La page met plusieurs secondes à s'ouvrir

L'instance s'était endormie : UptimeRobot ne la pingue plus. Vérifie que le moniteur est actif et toujours en Up.
